# Notes

## How the app is built

- **Rust, no TSX.** The whole app is a Rust crate (`src/`) on Native Shell's engine; `nsh.json` names its root
  component (`App`). No JavaScript VM ships in either app.
- **NSH from its Git tag.** The app depends on NSH 0.4.0 from `https://github.com/longbridge/nsh` tag `v0.4.0`, not
  crates.io: the crates.io package of `nsh-platform-ios` 0.4.0 does not compile (its `lib.rs` includes
  `../../nsh-platform-macos/src/speech.rs`, a file outside the published crate). The Git checkout is the same release.
  NSH itself is not modified.
- **iOS: an Xcode project around a Rust static library.** `ios/rust` is a `staticlib` crate whose
  `everbloom_main()` calls `nsh_platform_ios::run_app` with the app's root (what `nsh package` does in its own
  runner); `ios/Everbloom/main.m` calls it. I used this instead of `nsh package --target ios` because the spec needs
  things `nsh package` cannot set: App Transport Security for plain HTTP, portrait only, iPhone only, automatic
  signing from `DEVELOPMENT_TEAM` / `CODE_SIGNING_ALLOWED=NO`, and an `os_log` call for the log marker.
  The project was generated by xcodegen from `ios/project.yml` and is committed, so building needs no xcodegen.
- **Android: `nsh package` plus a manifest.** NSH's release manifest has no cleartext HTTP setting (it adds
  `usesCleartextTraffic` only to development builds) and allows every orientation. `android/package.sh` keeps NSH's APK
  contents (`classes.dex`, `libnsh.so`, assets) and links them with `android/AndroidManifest.xml`: NSH's manifest plus
  `usesCleartextTraffic="true"` and `screenOrientation="portrait"`.
- **Endpoint.** iOS reads `SHOP_API_URL` from the process environment at launch. Android uses `SHOP_API_URL` from the
  build environment (compiled in with `option_env!`; `build.rs` rebuilds when it changes). The iOS build script runs
  Cargo with a clean environment, so a `SHOP_API_URL` in the shell is never compiled into the iOS app.
- **Log marker.** `SHOPBENCH home_ready` is written with `os_log(OS_LOG_DEFAULT, …)` from `main.m`, once per process,
  on the frame after Home's data is set. Nothing else is logged by the app (NSH's runner logs nothing in release).

## Decisions where the spec is silent

- **Tab bar.** A custom bar drawn from the design (49 pt + safe area, the design's SVG icons, the badge). NSH's
  system `TabBar` uses SF Symbols / drawables and has no badge or test ids. Tabs are kept mounted and hidden, so each
  keeps its stack. The bar is hidden when the selected tab shows a product, and while the software keyboard is up
  (the content is padded above the keyboard, so the search results end at its top instead of under it).
- **Navigation.** Each of Home and Search is an NSH `nav_stack` (native `UINavigationController` / Android stack,
  native push animation and swipe back) with the system header hidden; pages draw the design's own bars. Collection
  and Search show the tab bar; Product hides it.
- **Collection screen.** The title comes from the collection tapped on Home (shown at once); the description and the
  sort chips sit above the grid, which is the scrolling container (`product-grid`). A sort change clears the grid and
  shows the skeleton until the first page of the new order arrives; answers to an older sort are dropped.
- **Infinite scroll** uses NSH's `virtual_list` `on_load_more` with its default threshold of one viewport. The
  "small loading indicator" is the text "Loading…" in `textMuted` at the end of the list (NSH has no activity
  indicator control and the spec allows no extra animation). A failed next page stops loading until the next scroll
  to the end.
- **Lazy rendering.** Collection grid and search results are `virtual_list`s (native recycling). Because test ids in
  NSH's Rust API are static, each cell rebuilds its card when it is given another row (`dynamic` over the row
  index), so `product-card-<i>` / `search-result-<i>` always name the row shown.
- **Pressables** are NSH views in the `button` role with `on_press` (NSH 0.4.0's Rust component builder has no
  `test_id`, while views do, and a pressable view is one accessibility element carrying its identifier).
  `product-carousel` is set on a group view around NSH's `carousel` (its parts take no test id).
- **Product.** The carousel is NSH's `carousel` (native paging scroll view) with page dots (only with 2+ images) and
  the round back button over it. The price uses the `sale` color with the compare-at price struck through when the
  compare-at is higher (as on cards). Option label is `<name>: <value>` with the value in `textMuted`. When no variant
  matches the combination exactly, the first variant with the tapped value is selected. Sections without data
  (description, recommendations) are left out.
- **Prices:** search rows and recommendation cards show the price only (as drawn); grid cards and best sellers show
  the sale treatment.
- **Featured banner** label is "Featured collection" drawn uppercase (the design's `text-transform`).
- **"See all"** next to "Collections" in the design is left out: the spec lists no such feature.
- **Empty cart** "Start shopping" (from the design's empty state) switches to the Home tab.
- **Search.** The text is trimmed before sending; an empty field shows the hint and no results. A new query replaces
  the results with skeleton rows once it is sent (after the 300 ms pause). Stale answers are dropped by a generation
  counter. Taps on a result work while the keyboard is up; dragging the list dismisses the keyboard.
- **Cart.** Steppers are disabled while a cart mutation is in flight (so quick taps cannot send stale quantities).
  "Add to cart" switches to the Cart tab once the server answered; a network failure of any cart mutation shows the
  alert "Couldn't update the cart. Check your connection and try again." (the spec only defines the `userErrors`
  alert, which shows the first message). The variant title line is omitted for `Default Title`.
- **Check out** opens `checkoutUrl` in the system browser (`open_url`): NSH has no in-app browser.
- **Loading states.** Home: the skeleton of `States.dc.html`, from the first frame. Collection: a skeleton grid.
  Product: a skeleton image and title with the back button. Search: skeleton rows. Error copy uses the spec's
  "Couldn't load products" (ASCII apostrophe).
- **Images** are requested with `width` exactly as the table says (1080 banner/carousel, 480 cards, 240 thumbnails
  and cart lines) and drawn aspect-fill on the `surface` color.
- **Launch screen** is the system's plain launch screen (`UILaunchScreen` empty, light appearance): white.
- **Debug key** signs the Android APK.

## Dependencies added

- `serde` (with `derive`): decoding the Storefront API's JSON into typed models.
- `serde_json`: building request bodies and parsing responses.

Nothing else: no UI kit, state library or GraphQL client. Requests are plain `POST`s through NSH's `fetch`
(NSURLSession on iOS, HttpURLConnection on Android). xcodegen was used once to generate the Xcode project; it is not
needed to build.

## Not met, or met with caveats

- **In-app browser:** NSH has none, so Check out opens the system browser (the spec's stated fallback).
- **Signed iOS build** could not be run here: this machine's Xcode account login is rejected, so automatic
  provisioning fails. The unsigned device build (`CODE_SIGNING_ALLOWED=NO`) and the simulator build succeed; the
  signed command is standard automatic signing.
- **Loading indicator** at the end of lists is a text, not a spinner (see above).
- **Accessibility labels of containers.** NSH reads the text inside a view as the label of a container without one,
  including the text of hidden tabs, so some "Other" elements in XCUITest carry long labels. Identifiers are
  unaffected; elements in hidden tabs are not exposed.
- **Android endpoint** is set at build time (allowed by the spec), not at launch.
