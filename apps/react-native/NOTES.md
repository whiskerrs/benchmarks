# Notes

## Dependencies added

The project was created with `npx @react-native-community/cli@20.2.0 init Everbloom --version 0.88.1`. Beyond `react` and `react-native`, the app has two runtime dependencies:

| Package | Version | Why |
|---|---|---|
| `react-native-safe-area-context` | 5.11.1 | Gets safe-area insets for the notch, home indicator and Android edge-to-edge bars. React Native's own `SafeAreaView` is deprecated, and its docs point to this package. The RN 0.88 template already includes it. |
| `react-native-svg` | 15.16.1 | Draws the design's vector icons (home, search, cart, back, plus the stepper's minus/plus and the empty/error glyphs) from the design's SVG paths. React Native has no vector drawing primitive. |

The dev dependencies are the template's tooling (CLI, Babel, Metro, TypeScript, ESLint, Prettier). I removed the template's Jest setup and its `@react-native/new-app-screen` dependency.

Things I deliberately left out:
- **No navigation library.** React Native has no built-in navigator, so `src/navigation.tsx` implements the tab bar and the per-tab stacks with plain views. Every route of every visited tab stays mounted, and only the top route of the active tab is shown (`display: 'none'` hides the rest). This keeps each tab's stack, state and scroll position when switching tabs. Android's hardware back pops the active stack.
- **No in-app browser library.** React Native has no in-app browser, so "Check out" opens `checkoutUrl` in the system browser with `Linking.openURL`, as the spec allows.

## Native code

- `specs/NativeShopBench.ts` is a Turbo Native Module spec (generated by codegen). It is implemented in `ios/Everbloom/RCTNativeShopBench.mm` and in `android/.../NativeShopBenchModule.kt`.
  - `getApiUrl()`: on iOS, returns `ProcessInfo.environment["SHOP_API_URL"]`. On Android, returns `BuildConfig.SHOP_API_URL`, which is set at build time from the `SHOP_API_URL` env var or Gradle property. An empty value means the default endpoint is used.
  - `markHomeReady()`: on iOS, calls `os_log(OS_LOG_DEFAULT, "SHOPBENCH home_ready")` guarded by `dispatch_once`, so it is written once per process in release builds too. Android writes the same line with `Log.i`. Home calls it in an effect after the first render that has loaded content.
- The app has no other logging: no `console.*` calls.
- iOS `Info.plist`:
  - `CADisableMinimumFrameDurationOnPhone = true`
  - `NSAllowsArbitraryLoads = true`, which allows plain HTTP
  - `UIUserInterfaceStyle = Light`
  - portrait only, iPhone only (`TARGETED_DEVICE_FAMILY = 1`)
  - the template's empty location usage string removed
- The launch screen is a plain white storyboard.
- Android manifest:
  - `usesCleartextTraffic="true"`
  - portrait
  - light AppCompat theme, not DayNight, because there is no dark mode
- The app icons are the template defaults (no custom icon).

## Decisions where the spec is silent

- **GraphQL documents.** Each request sends its operation exactly as written in `spec/storefront.graphql`, plus only the fragments that operation uses. GraphQL rejects documents that contain unused fragments, so sending the whole file is not possible.
- **Request timeout.** API requests time out after 15 s, so an unreachable endpoint shows the error state in reasonable time. GraphQL `errors` with no `data`, non-2xx responses, timeouts and network errors all count as failures.
- **"See all"** in the design's Collections header is not shown. The spec does not list it and gives it no destination.
- **Error text.** "Couldn't load products" uses the spec's ASCII apostrophe. The design uses a typographic one.
- **Sale styling.** The sale rule (price in the `sale` color, compare-at price struck through) applies to every product card: Home, Collection, recommendations and search rows. The spec says Collection uses "the same card as Home"; I used the same price rendering everywhere for consistency.
- **Collection screen.**
  - The nav bar is fixed. The description and sort chips scroll with the grid as the list header.
  - Sort chips and collection chips are horizontal scroll rows, because they are wider than the screen.
  - The nav bar first shows the title passed from Home, then the title from the response.
- **Lazy lists.** These use `FlatList` with `windowSize={5}`, `initialNumToRender` 6–8 and `onEndReachedThreshold={1}` (one visible length from the end).
- **Next-page errors.** If loading the next page fails, the list stays and a Retry button (`error-retry`) appears in its footer.
- **Search.**
  - The field is an uncontrolled `TextInput`. With a controlled one, fast automated typing (`typeText`) dropped characters.
  - Requests use the trimmed text. Each response is checked against the current query, and stale ones are discarded.
  - Typing a new query replaces the results with a spinner while the first page loads.
- **Product screen.**
  - The page dots appear only when there is more than one image. Tapping a dot scrolls to that image.
  - Selecting a pill picks the variant whose `selectedOptions` all match the current selection with that one value changed. If no variant matches exactly, it picks the first variant that has the tapped value.
  - "You may also like" is hidden when there are no recommendations.
  - While loading, the screen shows a spinner with the back button. The error state also keeps the back button.
- **Cart.**
  - "Add to cart" switches to the Cart tab only after the mutation succeeds. On failure it stays on the product page and shows an alert.
  - Cart mutations run one at a time. The stepper and Add button are disabled while one is in flight.
  - A network failure during a cart mutation shows an alert ("Couldn't update cart").
  - A response with `cart: null` keeps the current cart and shows the first user error.
  - The variant title shown on a cart line is the API's `title` (for example "XS"), omitted when it is "Default Title".
  - The empty-cart state's "Start shopping" button switches to the Home tab, as in the design.
- **Tab bar.** Tapping the active tab does nothing; it does not pop to root. The cart badge is drawn next to the tab button, not inside it, so XCUITest can see `cart-badge` as its own element.
- **No animations.** Pushing and popping screens are instant, because there is no framework default transition without a navigation library.
- **Variant prices.** No product in the `apparel-large-catalog` mock data has variants with different prices, so switching variants changes the selection but never visibly changes the price. The code shows the selected variant's `price` and `compareAtPrice`.

## Not met / limitations

- The signed device build (`DEVELOPMENT_TEAM` set) could not be checked here, because no Apple team was configured for this run. The unsigned device build (`CODE_SIGNING_ALLOWED=NO`) and the Simulator build were both built and verified.
- On Android, the endpoint is a build-time setting only (allowed by the spec).
- Android maps `testID` to the view tag / resource-id that React Native sets. Only the iOS identifiers were checked with XCUITest.
